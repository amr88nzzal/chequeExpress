## 1. الهدف والنطاق

### 1.1 الهدف
نظام ويب لإدارة **الشيكات الصادرة والواردة** لعدة شركات وبنوك وعملات ودول، مع **طباعة بيانات الشيك الصادر على الشيك الفعلي** (الشيك مرقّم مسبقاً من البنك، يُدخَل في الطابعة، والنظام يطبع الحقول في أماكنها). يحلّ محل ملف إكسل يُستخدم اليوم للإدخال والطباعة وتوقع الرصيد.

### 1.2 الأدوار والصلاحيات ✅
ثلاثة أدوار أساسية، وفوقها **صلاحيات دقيقة** بصيغة `cheques.<resource>.<action>`، والأدوار الثلاثة قوالب جاهزة منها (قرار معتمد).

| الصلاحية | مدير (Admin) | مصدر شيكات | متابع شيكات |
|---|:-:|:-:|:-:|
| إدارة المستخدمين والأدوار والإعدادات | ✔ | | |
| الشركات والحسابات البنكية والدفاتر | ✔ | | |
| تصميم تخطيطات الطباعة والمعايرة | ✔ | | |
| إنشاء وتعديل مسودة شيك صادر | ✔ | ✔ | |
| طلب الاعتماد | ✔ | ✔ | |
| اعتماد شيك صادر | ✔ | 🔶 اختياري | |
| طباعة شيك صادر | ✔ | ✔ | |
| إعادة طباعة (بسبب إلزامي) | ✔ | 🔶 بإذن | |
| إلغاء / إتلاف شيك | ✔ | قبل الطباعة فقط | |
| تغيير حالة (تسليم، صرف، ارتجاع، تجيير، إيداع، تحصيل) | ✔ | | ✔ |
| تسجيل شيك وارد | ✔ | | ✔ |
| إدخال رصيد الحساب البنكي | ✔ | | ✔ |
| إدارة المستفيدين/الأطراف | ✔ | ✔ | عرض فقط |
| التقارير والتصدير | ✔ | ✔ | ✔ |

- يُمنح الدور على **نطاق**: كل الشركات، أو شركة، أو حساب بنكي.
- المتابع **لا يعدّل** المبلغ أو المستفيد ولا يطبع.

### 1.3 الإصدارات
**الإصدار 1 (ويب + PWA)**
- المنظمات والشركات والبنوك والحسابات والدفاتر، المستفيدون/الأطراف
- شيكات صادرة بدورة كاملة + طباعة بملف PDF بمقاس فعلي + معايرة
- شيكات واردة (تسجيل، إيداع، تحصيل، ارتجاع، تجيير)
- التفقيط (عربي/إنجليزي) متعدد العملات
- توقع الرصيد النقدي برصيد يدوي
- تنبيهات الاستحقاق، التقارير والتصدير، **استيراد من الإكسل الحالي**
- PWA للموبايل: متابعة وتغيير الحالات وصور الشيكات
- **Print Agent** لسطح المكتب (طباعة صامتة، والطباعة من الموبايل عبره) — المرحلة C6

**الإصدار 2**
- ملف القيود اليومية للمحاسبة (Excel/CSV عام قابل لضبط الأعمدة)
- مطابقة كشف الحساب البنكي، قراءة الشيك الوارد من الصورة (OCR)

**لاحقاً:** ربط مباشر ببرنامج محاسبي، Webhooks/API عامة، فوترة SaaS.

### 1.4 المتطلبات غير الوظيفية
- **الدقة المالية:** لا floating point إطلاقاً. المبالغ أعداد عشرية دقيقة.
- **عدم فقدان الأثر:** لا حذف فعلي لشيك أو ورقة شيك. كل تغيير حالة مسجَّل.
- **التدقيق:** كل تعديل وكل طباعة وكل كشف لبيانات حساسة.
- **API-first** موثّق بـ OpenAPI.
- **عربي/إنجليزي مع RTL**، وتقويم هجري للعرض اختيارياً.
- **قابلية النقل:** حاويات وإعدادات خارجية.

## 2. القرارات

### 2.1 المعتمدة ✅

| القرار | الخلاصة |

| استقلال المشروع | لا ربط مع نظام HR |
| التقنيات | React · Node.js · Express · PostgreSQL |
| الاعتماد قبل الطباعة | **اختياري بإعداد لكل شركة** |
| المستفيدون | مشتركون بين شركات المستأجر، مع إمكانية جعل مستفيد **خاصاً بشركة** |
| الحساب المحاسبي للمستفيد | اسم ورقم الحساب يُستخدمان في: التقارير والتصدير، ملف قيود يومية، وربط مباشر لاحقاً |
| مستوى الاعتماد | مستوى واحد (معتمِد واحد) |
| نطاق الإصدار الأول | **الأردن (الدينار) أولاً بقالب البنك العربي**؛ بقية الدول والعملات إعداد لاحق (التصميم يبقى متعدد الدول والعملات) |
| معمارية السيرفر | **arm64** |
| أسلوب كتابة الفلسات | رقمي افتراضياً («و 515 فلس»)، وبالأحرف خيار بالإعداد |
| عبارة الإغلاق بعد المبلغ كتابةً | تُضبط في قالب الطباعة لكل بنك |
| ترقيم الشيك عند الطباعة | النظام يقترح الرقم التالي من الدفتر **ويطلب تأكيده** |
| رصيد الحساب البنكي | إدخال يدوي أولاً (كالإكسل) |
| إثبات التسليم | اختياري: صورة أو توقيع المستلم |
| المنصات | ويب أساساً، موبايل للمتابعة، سطح مكتب عند عجز الويب عن الطباعة |
| الطابعة | ليزرية هي الأساس |
| برنامج الطباعة (Agent) | ضمن الإصدار 1 (المرحلة C6)، **Windows فقط**، تطبيق في شريط المهام بواجهة صغيرة |
| ملف القيود اليومية | Excel/CSV عام قابل لضبط الأعمدة |
| الاستيراد من الإكسل | بعد الصادرة مباشرة (المرحلة C4) |
| النشر | سيرفر خاص بـ Docker Compose |
| تعدد المستأجرين | `tenant_id` وRLS من أول جدول |
| الأدوار | صلاحيات دقيقة من البداية، والأدوار الثلاثة قوالب جاهزة، وللمستأجر لاحقاً أدوار خاصة |
| توقع الرصيد | يختار المستخدم لكل تقرير: الصادرة غير المصروفة فقط، أو الصادرة + الواردة المستحقة |

### 2.2 تقنية (مقترحة على نمط HR) 🔶
TypeScript في كل مكان · pnpm monorepo · Mantine (RTL) · Kysely مع ترحيلات SQL · pg-boss للمهام · معرّفات UUIDv7 · مبالغ `numeric(18,4)` وتُنقل في الـ API كنص عشري · `decimal.js`.

### 2.3 بانتظار الموافقة 🔶
1. **جدول واحد للأطراف** (`parties`): يصلح مستفيداً في الصادر وساحباً في الوارد.
2. **ورقة شيك لكل رقم** (`cheque_leaves`): تجعل الفجوات والتالف والمخزون بسيطة.
3. **المُعتمِد غير المُنشئ** (إعداد لكل شركة).

## 3. نموذج البيانات (مستوى عالٍ، نحو 35 جدولاً)

الهرم: **tenant ← companies ← bank_accounts ← cheque_books ← cheque_leaves**.

**المنصة والهوية**
`tenants`, `users`, `memberships`, `roles`, `permissions`, `role_permissions`, `role_assignments` (بنطاق شركة/حساب), `audit_logs`, `files`, `settings` (مستأجر/شركة/مستخدم), `notifications`, `job_runs`.

**المنظمة والمال**
- `countries` و`currencies` (خانات الكسر، حزمة الدولة)
- `banks` (فهرس عام بالدولة)
- `companies` (دولة، عملة أساسية، منطقة زمنية)
- `bank_accounts` (شركة، بنك، اسم الفرع، رقم الحساب، IBAN، العملة) — **حقلا الحساب مشفّران**
- `account_balance_entries` (حساب، التاريخ، المبلغ، ملاحظة)

**الأطراف**
`parties`: نطاق (`company_id` اختياري = خاص بشركة)، السابقة (`سادة/سيد/سيدة/بدون`)، الاسم، الاسم الإنجليزي (اختياري)، اسم الحساب المحاسبي، رقم الحساب المحاسبي، هاتف، بريد، أعلام الاستخدام (مستفيد/ساحب)، نشط.
صيغة الاحترام تُشتق من السابقة (المحترمين/المحترم/المحترمة) وقابلة للتعديل. **«بدون»** خيار رابع لأن 13 من 150 سطراً في الإكسل بلا سابقة ولا لاحقة.

**الدفاتر**
- `cheque_books` (حساب، من رقم إلى رقم، حالة، عهدة مستخدم، تاريخ الاستلام)
- `cheque_leaves` (دفتر، الرقم، الحالة: متاحة/محجوزة/مستخدمة/تالفة/ملغاة)

**الصادر**
- `issued_cheques` (شركة، حساب، ورقة الشيك بعد الحجز، الطرف، المبلغ، العملة، تاريخ الإصدار، تاريخ الاستحقاق، الملاحظة، الحالة، المعتمِد، عدد الطبعات، التسليم، مرجع محاسبي)
- `cheque_status_history` (للصادر والوارد: من، إلى، السبب، المستخدم، الوقت)
- `print_jobs` (الشيك، إصدار التخطيط، ملف الطابعة، القناة: ويب/Agent، الحالة، النتيجة)
- `delivery_proofs` (ملف صورة/توقيع، المستلم)

**الوارد**
- `received_cheques` (الساحب، البنك، رقم الشيك، المبلغ، العملة، تاريخ الاستلام، الاستحقاق، الحالة، حساب الإيداع، تاريخ الإيداع والتحصيل، سبب الارتجاع)
- `endorsements` (الشيك، الطرف المجيَّر له، التاريخ، ملاحظة)
- `cheque_files` (صور الوجهين)

**الطباعة**
- `cheque_layouts` (مستأجر أو مكتبة المنصة، البنك، المقاس بالمم، الخلفية، الإصدار)
- `cheque_layout_fields` (الحقل، x/y/العرض بالمم، المحاذاة، الخط والحجم، الاتجاه، أقصى عدد أسطر، تنسيق التاريخ/المبلغ)
- `printer_profiles` (إزاحة أفقية/رأسية، تحجيم، اتجاه التغذية، ملاحظة الدرج)
- `restriction_phrases` (عبارات التقييد مثل «لا يصرف إلا للمستفيد الأول وبتاريخه»)
- `currency_words` (لكل عملة ولغة: المفرد والجمع والجنس ووحدة الكسر)
- `print_agents` (المستأجر، الجهاز، رمز الجهاز المجزّأ، آخر اتصال، الطابعات المكتشفة، الحالة)

**التصدير**
`accounting_exports` (دفعة، النوع، الفترة، الحالة، الملف)، لاحقاً: `webhooks`.

## 4. دورة حياة الشيك

### 4.1 الصادر
```
مسودة → [بانتظار الاعتماد] → معتمد → مطبوع → مُسلَّم → مصروف
```
(حالة الاعتماد تُتجاوز إذا لم يُفعَّل في الشركة.)

| من | إلى | بإذن |
|---|---|---|
| مسودة/معتمد | ملغى | مصدر (قبل الطباعة) |
| مطبوع | **تالف** (يُستهلك رقمه ويبقى) | مدير |
| مطبوع/مُسلَّم | مفقود، موقوف الصرف | متابع/مدير |
| مُسلَّم | مصروف، مرتجع، استُبدل بنقد | متابع/مدير |

- **قيد الطباعة:** بعد إرسال الطباعة يبقى الشيك «قيد الطباعة» حتى يؤكد المستخدم نجاحها أو يعلّمه تالفاً. تعلق الورقة أحياناً، وبدون هذا التأكيد تضيع الأرقام.
- الإلغاء بعد الطباعة غير متاح، المتاح هو «تالف» مع سبب وصورة اختيارية.
- كل انتقال يُسجَّل في `cheque_status_history`، ولا انتقال خارج الجدول.
- **مطابقة حالات الإكسل الحالية:**
  - **«غير مستلم»** ✅ = شيك **مطبوع وموقَّع وجاهز للتسليم** لكن المستفيد لم يستلمه بعد (محفوظ في خزنة الشيكات) ← حالة `printed`، وعرضها في الواجهة «مطبوع / جاهز للتسليم». يبقى محسوباً كالتزام قائم في توقع الرصيد.
  - **«نقداً»** ✅ = استُرد الشيك من المستفيد ودُفعت قيمته نقداً، فالشيك **بحكم التالف أو الملغى** ← حالة `replaced_by_cash` (من `delivered` فقط)، سبب إلزامي (ومرجع الدفع النقدي اختياري)، وتصبح ورقته غير صالحة للاستعمال ويبقى رقمها في السجل، ولا يُحتسب في توقع الرصيد.
  - **في الإكسل «نقدا» و«مرفوض» ليسا حالتين مستقلتين بل سببان فرعيان لـ «ملغي»** (عمود «رفض؟»). والمطابقة الكاملة في `IMPORT_EXCEL.md` القسم 4: ملغي+مرفوض ← `returned` ✅، ملغي بلا سبب ← `spoiled` ✅، الوضع الفارغ ← `delivered` ✅؛ ويبقى **بانتظار التأكيد**: مسحوب ← `cleared`، ومبلغ بلا رقم ← `draft`.

### 4.2 الوارد
```
بحوزتنا → مودع → محصَّل
```
مخارج: مرتجع (مع السبب)، مجيَّر لطرف ثالث (سلسلة تجيير)، معاد للساحب.
- منع التكرار: البنك + رقم الشيك + الساحب فريدة ضمن الشركة (تحذير قابل للتجاوز بسبب).

### 4.3 ترقيم الشيك الصادر
1. عند الطباعة يقترح النظام **أول ورقة متاحة** في دفتر الحساب المختار.
2. يطلب من المستخدم إدخال **آخر ثلاثة أو أربعة أرقام من الشيك الموضوع في الطابعة** للتأكد.
3. تُحجَز الورقة بقفل صفّي (`FOR UPDATE SKIP LOCKED`) فلا يحصل مصدران على الرقم نفسه.
4. تصبح الورقة «مستخدمة» عند تأكيد الطباعة، و«تالفة» عند الإتلاف.
5. التقارير تُظهر **الفجوات** في التسلسل.

## 5. الطباعة

### 5.1 المبدأ
- ناتج الطباعة **ملف PDF بمقاس الشيك الفعلي بالمم**، بلا تحجيم، ويحتوي **النص فقط** (الخلفية تُستخدم للمعاينة ولا تُطبع).
- التخطيط بالمم، لكل بنك، ويُصمَّم على صورة الشيك كخلفية.
- الحقول القياسية: التاريخ، المستفيد، المبلغ كتابةً (سطر أول وثانٍ، بأقصى عدد أسطر)، المبلغ رقماً (خانة الدينار وخانة الفلس أو خانة واحدة)، الملاحظة، عبارة التقييد.
- **حماية من التلاعب:** خيار إكمال السطر الباقي من سطر الكتابة برموز (مثل `***`).
- رقم الشيك وسطر MICR والتوقيع وختم التسطير **لا يطبعها النظام**.

### 5.2 المعايرة (الليزر)
- الطابعات الليزرية لها هوامش غير قابلة للطباعة، وتتفاوت في الإزاحة بين الأجهزة والأدراج.
- `printer_profile` لكل طابعة/درج: إزاحة أفقية ورأسية بالمم، تحجيم، اتجاه التغذية.
- **صفحة اختبار** تُطبع على ورق عادي، يُوضع فوقها شيك فارغ ضد الضوء لقياس الإزاحة، ثم تُحفظ القيم.
- المعاينة على الشاشة تُظهر الخلفية والحقول بمواضعها بعد الإزاحة.
- **وضعا الورق** 🔶: (أ) ورقة مخصصة بمقاس الشيك، (ب) صفحة A4 يوضع الشيك في موضع محدد منها (أصل الإحداثيات `x0,y0` في ملف الطابعة). **الإكسل الحالي يطبع على A4 أفقي بهوامش صفر وتحجيم 66%** وبخط Arial غامق (12–16)، **قرار صاحب المشروع: الشيك يُدخل مباشرة من الدرج اليدوي كورقة صغيرة**، فالوضع الافتراضي هو (أ) ورقة مخصصة بمقاس الشيك، ويبقى (ب) احتياطاً إن لم يدعم تعريف الطابعة حجماً مخصصاً أو كان تحجيم 66% في الإكسل حيلة لمطابقة موضع الشيك على A4. يُحسم بالمعايرة الفعلية.
- **دروس نموذج PDF (C0):** (1) Chromium يقرّب حجم الصفحة إلى بكسلات CSS (±0.26 مم) والمحتوى مثبّت من أعلى اليسار فلا أثر على المواضع؛ (2) **أي محتوى يتجاوز الصفحة (بسبب الإزاحة) يجعل Chromium يصغّر الصفحة كلها صامتاً**، لذلك تُوضع الورقة داخل حاوية بحجم الصفحة و`overflow:hidden`؛ (3) دقة المواضع ضمن 0.13 مم؛ (4) تشكيل الحروف العربية والخطوط المضمَّنة سليمان.

### 5.3 الطباعة من الويب (الإصدار 1)
حوار طباعة المتصفح مع **ملف PDF بحجم فعلي**، وتعليمات واضحة لاختيار الطابعة والدرج. هذا لا يضمن طباعة صامتة، لذلك الـ Agent في الإصدار 1 (المرحلة C6)، وتبقى هذه الطريقة خياراً احتياطياً.

### 5.4 Print Agent (الإصدار 1، المرحلة C6)
- برنامج صغير على الكمبيوتر المتصل بالطابعة، يُسجَّل بحساب المستأجر برمز جهاز.
- **Windows فقط**، تطبيق في شريط المهام بواجهة صغيرة (اختيار الطابعة والدرج، الحالة، المعايرة)، بمثبّت موقَّع رقمياً.
- مسار الطباعة الصامتة (SumatraPDF/`pdf-to-printer` أو واجهات Windows الأصلية) يُحسم بنموذج أولي في C0 بشرط الحجم الفعلي بلا تحجيم.
- يستقبل أوامر الطباعة من الخادم ويطبع بصمت ويُرجع النتيجة (نجحت/فشلت).
- يحفظ ملف المعايرة ولا يخزّن بيانات الشيكات على القرص.
- **الطباعة من الموبايل:** الموبايل يرسل الأمر إلى الخادم ثم إلى الـ Agent، فلا تحتاج الطباعة إلى إعداد على الهاتف.

### 5.5 إعادة الطباعة
بصلاحية وسبب إلزامي، يُزاد `print_count` ويُسجَّل في التدقيق.

**قرار صاحب المشروع ✅: المستخدم يحدّد الخيار المناسب وقت الإعادة**، لأن الورقة قد تتلف أو قد تتعطل الطابعة قبل سحبها. تُعرض عليه شاشة «ماذا حدث للورقة؟» بالخيارات التالية (السبب إلزامي في كلها، وكلها تُدقَّق):

| الحالة الواقعية | الخيار | أثره على الورقة |
|---|---|---|
| الطابعة تعطلت **قبل سحب الورقة** (الورقة سليمة وفارغة) | **إعادة إرسال على نفس الورقة** | تبقى `reserved`، ويُعاد التحقق من آخر أرقام الشيك، و`print_count` يزيد |
| الورقة سُحبت وطُبعت خطأً أو تلفت أو انحشرت | **ورقة جديدة** | الأولى تصبح `spoiled` برقمها وسببها، وتُحجز التالية ويتغير رقم الشيك (يُسجَّل الرقمان في السجل) |
| أمر طباعة لم تُدخَل ورقته أصلاً ولن يُطبع | **إلغاء أمر الطباعة** (`printing → approved`) | تُحرَّر الورقة `available` |

- **«نفس الورقة» متاح فقط ما دام الشيك `printing`** (قبل تأكيد الطباعة). بعد التأكيد (`printed`) صار على الورقة حبر، فالإعادة **بورقة جديدة فقط**.
- الصلاحيات: `issued.cheque.reprint` تشمل الخيارين، ويُعطى افتراضياً للمدير والمُصدر 🔶، ويمكن للمستأجر حصر «ورقة جديدة» بالمدير عبر صلاحية منفصلة `issued.cheque.reprint-new-leaf`.

## 6. التفقيط

- حزمة مستقلة `packages/words` بـ TypeScript: عربي وإنجليزي، تعتمد **الأعداد العشرية الدقيقة** لا floating point.
- كل عملة ولغة لها ملف يحدد: المفرد، الجمع، الجنس، وحدة الكسر (مفرد/جمع/جنس)، عدد خانات الكسر.
- أسلوب الكسر ✅: **بالأرقام افتراضياً («و 515 فلس») كما في الإكسل**، وخيار «بالأحرف» متاح بالإعداد (الكسر الاعتيادي لاحقاً).
- **عبارة الإغلاق** (فقط / فقط لا غير) ✅ ليست جزءاً من التفقيط، بل **تُضبط في قالب الطباعة لكل بنك** وتُلحق بالسطر الأخير.
- **الاختبارات الذهبية** تُبنى من مخرجات وحدة VBA الحالية كمرجع (ماكرو يصدّر آلاف الحالات من ملفك)، ثم تُراجَع الحالات التي تخطئ فيها.
- مثال من ملفك: `3355.515` دينار ← «ثلاثة آلاف وثلاثمائة وخمسة وخمسون دينارا و 515 فلس فقط» + «لا غير».
- ملاحظة: النسخة الإنجليزية الحالية فيها خطأ إملائي (`thousund`)، وتصحَّح.

## 7. المنصات والواجهة

**الويب (أساسي):** لوحة، الشيكات الصادرة (قائمة وتفاصيل وإنشاء)، الطباعة (معاينة ومعايرة)، الواردة، المستفيدون/الأطراف، دفاتر الشيكات، توقع الرصيد، التقارير، الإعدادات، مصمم التخطيط، المستخدمون والأدوار، عارض التدقيق، معالج الاستيراد.

**سطح المكتب:** الـ Agent فقط (الإصدار 1، المرحلة C6).

## 8. المهام الخلفية والتقارير

- تنبيهات: استحقاق الصادر والوارد خلال N يوماً، شيكات مسلَّمة لم تُصرف، رصيد متوقع سالب.
- ملخص يومي بالبريد.
- **توقع الرصيد:** رصيد الحساب المُدخَل − الصادرة غير المصروفة حسب تاريخ الاستحقاق، مع الفائض أو العجز بعد كل شيك (كورقة Accrued_checks). **يختار المستخدم لكل تقرير** هل تُضاف الواردة المستحقة.
- **قواعد منقولة من ورقة Accrued_checks** 🔶 (التفاصيل في `IMPORT_EXCEL.md` القسم 5): الشيك المصروف لا يُخصم ثانية (الرصيد المُدخَل يعكسه)، وغير المصروف يُخصم عند تاريخه، و**الشيك غير المسلَّم الذي فات تاريخ استحقاقه يُعدّ تاريخه الفعلي اليوم**. وتُضاف **بنود متوقعة يدوية** (مثل «visa + master» و«إيداعات أخرى») بتاريخ ومبلغ.
- التقارير: المستحق، الصادر غير المصروف، المرتجع، كشف حساب لكل طرف، فجوات الدفاتر، الشيكات التالفة، التدفق النقدي.
- التصدير: Excel/CSV بالأعمدة المحاسبية (اسم ورقم الحساب المحاسبي).

## 9. التحويل إلى SaaS

- `tenant_id` + RLS في كل الجداول (قرار معتمد).
- **مكتبة قوالب شيكات** عامة على مستوى المنصة، يستنسخ منها المستأجر ويعدّل.
- القواعد حسب الدولة (صيغ، أعراف) **بيانات في حزم إعدادات** لا كود.
- إعدادات متدرجة: منصة ← مستأجر ← شركة ← مستخدم.
- الـ Agent يُسجَّل لكل مستأجر.
- لاحقاً: onboarding، حصص وخطط، فوترة، اختبارات عزل بين المستأجرين، تصدير بيانات المستأجر.

## 10. الأمان

- تشفير **رقم الحساب وIBAN** في القاعدة، وإظهار جزء منه في الواجهة، وكشفه كاملاً بصلاحية ويُدقَّق.
- JWT مع Refresh دوّار، 2FA اختياري، حدود معدل.
- التدقيق غير قابل للتعديل (كل طباعة وتغيير حالة وإلغاء).
- الملفات (صور الشيكات والتواقيع) خاصة بروابط موقّعة قصيرة العمر.
- `Idempotency-Key` لتأكيد الطباعة وتغيير الحالة.
- الـ Agent: رمز جهاز قابل للإلغاء، ولا يستقبل إلا أوامر موقّعة.

## 11. الاستيراد من الإكسل الحالي

معالج استيراد بتجربة قبل التنفيذ (Dry Run) وتقرير أخطاء:
- ورقة «أصحاب الإستحقاق» ← الأطراف + الشيكات الصادرة (الاسم، المبلغ، التاريخ، رقم الشيك، الحالة).
- ورقة Accrued_checks ← إدخالات رصيد الحساب.
- يُستخرج من الاسم «السادة … المحترمين» السابقة والاسم الصافي.
- حالات الإكسل تُطابَق مع حالات النظام بعد الإيضاح.
