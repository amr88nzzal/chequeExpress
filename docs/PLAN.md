## المرحلة C0: الإعداد والنماذج الأولية

**الهدف:** بيئة تعمل من اليوم الأول، وحسم أعلى المخاطر قبل البناء.

**النطاق:**
- مستودع GitHub وpnpm monorepo (`apps/api`, `apps/web`, `packages/words`, `packages/shared`, `infra`, `docs`)، نقل وثائق المشروع إلى `docs/`.
- ESLint/Prettier/tsc، Conventional Commits، Docker Compose (postgres، api، worker)، GitHub Actions (اختبار وبناء ونشر Staging على السيرفر الخاص).
- هيكل API فارغ: غلاف الاستجابة والأخطاء و`requestId` و`/health`.
- **نماذج أولية:**
  1. **الطباعة:** PDF بمقاس الشيك الفعلي بالمم، طباعته على **طابعتك الليزرية** على شيك فعلي (أو ورق بمقاسه)، وقياس الإزاحة، وتحديد هل يبقى حوار المتصفح خياراً احتياطياً بعد الـ Agent.
  2. **التفقيط:** حزمة `packages/words` أولية + ماكرو يصدّر حالات من ملفك + اختبارات ذهبية.
  3. **RLS:** `tenant_id` وسياسة RLS وسياق المستأجر مع Kysely وتوليد الأنواع و`uuidv7()`.
  4. **الواجهة:** Mantine مع RTL (جدول، نموذج، تاريخ).
  5. **طباعة الـ Agent على Windows:** طباعة PDF صامتة بحجم فعلي بلا تحجيم إلى طابعتك الليزرية (SumatraPDF/`pdf-to-printer` مقابل واجهات Windows الأصلية)، وهل تصمد الإزاحة نفسها بين طباعة المتصفح والـ Agent.
  6. **arm64:** بناء ونشر الصور على السيرفر (arm64): تشغيل Chromium/Playwright وتوليد PDF بخطوط عربية مضمَّنة، وسرعة التوليد (قبل اعتماد مكتبة PDF).

**معيار القبول:** `git push` يبني وينشر صفحة فارغة وAPI صحي على Staging؛ شيك يُطبع على الورق الفعلي بدقة ≤ 1 مم بعد المعايرة؛ التفقيط يطابق وحدة VBA في كل الحالات المصدَّرة إلا المختلفات الموثّقة؛ اختبار RLS يثبت العزل.

## المرحلة C4: الاستيراد من الإكسل الحالي

**الهدف:** نقل بياناتك الحالية، واستخدامها لاختبار ما بعدها.

**النطاق:**
- معالج استيراد بتجربة قبل التنفيذ (Dry Run) وتقرير أخطاء وإعادة تشغيل آمنة (idempotent).
- ورقة «أصحاب الإستحقاق» ← الأطراف + الصادرة. ورقة Accrued_checks ← إدخالات الرصيد.
- استخراج السابقة والاسم الصافي من «السادة … المحترمين».
- مطابقة حالات الإكسل مع حالات النظام حسب `docs/IMPORT_EXCEL.md`: «غير مستلم» ← `printed` و«نقداً» ← `replaced_by_cash` ✅ (موضّحان)، والوضع الفارغ ← `delivered` و«مرفوض» ← `returned` و«ملغي» بلا سبب ← `spoiled` ✅ (مؤكَّدة)، ويبقى **بانتظار التأكيد**: «مسحوب» ← `cleared`، والمسودات الخمسون، والأوراق المخفية.
- **تطبيع أسماء الأطراف وتوحيدها** (150 سطراً = 39 اسماً مختلفاً، و13 بلا سابقة)، و**تقريب المبالغ** قبل الحفظ (46 من 150 فيها ضجيج عشري، أقصاه `1e-11`).
- الأسطر بمبلغ بلا رقم شيك (50 سطراً) تُستورد **مسودات** 🔶.

**معيار القبول:** استيراد ملفك الفعلي (نحو ألف سطر) بتقرير أخطاء؛ مجاميع المبالغ تطابق الإكسل بالفلس؛ إعادة الاستيراد لا تكرر السجلات.

- **الخلفية:** توليد PDF بالمقاس الفعلي (نص فقط)، ربط التفقيط، حقول المبلغ (سطران، رقماً بخانتين أو واحدة)، **عبارة الإغلاق (فقط / فقط لا غير) كإعداد في كل تخطيط**، **شاشة «ماذا حدث للورقة؟» عند إعادة الطباعة** (نفس الورقة قبل التأكيد، أو ورقة جديدة، أو إلغاء الأمر)، إكمال السطر بالرموز، الإزاحة والتحجيم من `printer_profile`، `print_jobs` مع **تأكيد الطباعة أو الإتلاف**، إعادة الطباعة بسبب وصلاحية، `print_count`.
- **الواجهة:** **مصمم التخطيط** (رفع صورة الشيك كخلفية، سحب الحقول بالمم، حفظ إصدارات)، ملفات الطابعات وصفحة المعايرة، معاينة، شاشة الطباعة (تأكيد آخر أرقام الشيك)، الطباعة على دفعة، تخطيط البنك العربي كأول قالب.

**معيار القبول:** طباعة شيك البنك العربي على الليزر بدقة ≤ 1 مم؛ ورقة تعلق فتُعلَّم تالفة ويبقى رقمها في السجل؛ إعادة الطباعة تتطلب سبباً وتظهر في التدقيق؛ التخطيط الجديد لبنك ثانٍ يُنشأ من الواجهة دون كود.

## المرحلة C6: برنامج الطباعة على سطح المكتب (Print Agent)

**الهدف:** طباعة صامتة بالمقاس الفعلي، والطباعة من الموبايل عبر كمبيوتر المكتب.

**النطاق:**
- **القاعدة:** `print_agents` (المستأجر، الجهاز، رمز الجهاز المجزّأ، آخر اتصال، الطابعات المكتشفة، الحالة).
- **الخلفية:** تسجيل الجهاز برمز مؤقت يُنشئه المدير، قناة اتصال لأوامر الطباعة (WebSocket أو polling بتراجع)، أوامر موقّعة قصيرة العمر، نتيجة الطباعة (نجحت/فشلت) تغذّي تأكيد الطباعة، إلغاء رمز الجهاز، تحديث الإصدارات.
- **البرنامج (Windows فقط):** تطبيق في شريط المهام بواجهة صغيرة، بمثبّت موقَّع رقمياً، على الكمبيوتر المتصل بالطابعة: اكتشاف الطابعات واختيار الدرج، طباعة PDF بمقاس فعلي بلا تحجيم، حفظ ملف المعايرة، لا يخزّن بيانات الشيكات على القرص، سجل محلي مختصر، تحديث تلقائي.
- **الواجهة:** شاشة الأجهزة والطابعات، اختيار الجهاز/الطابعة عند الطباعة، حالة الاتصال، **الطباعة من الموبايل** (الأمر يصل إلى جهاز المكتب).

**معيار القبول:** شيك يُطبع بنقرة من الويب ومن الموبايل دون حوار طباعة؛ جهاز مفصول يُعرض بوضوح ولا تضيع الأوامر (تبقى في الطابور أو تنتهي صلاحيتها)؛ إلغاء رمز الجهاز يوقفه فوراً؛ فشل الطباعة يُبقي الشيك «قيد الطباعة» لا «مطبوع».

## المرحلة C8: توقع الرصيد والتنبيهات والتقارير والتصدير

**الهدف:** المتابعة المالية اليومية بدل ورقة Accrued_checks.

**النطاق:**
- **توقع الرصيد** لكل حساب: الرصيد المُدخَل − الصادرة غير المصروفة، مع **خيار لكل تقرير** لإضافة الواردة المستحقة، وإظهار الفائض/العجز بعد كل شيك.
- التنبيهات (داخل التطبيق، بريد، Web Push): الاستحقاق القريب، مسلَّم لم يُصرف، عجز متوقع، والملخص اليومي.
- التقارير: المستحق، الصادر غير المصروف، المرتجع، كشف حساب لكل طرف، فجوات الدفاتر، التالف، التدفق النقدي.
- التصدير: Excel/CSV بالأعمدة المحاسبية، والتصدير الكبير كمهمة خلفية.

**معيار القبول:** توقع الرصيد يطابق ورقة Accrued_checks لنفس البيانات؛ كل تقرير يحترم النطاق والمستأجر؛ تصدير 50 ألف صف دون ضغط ذاكرة.
