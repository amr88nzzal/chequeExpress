# @cheques/words — التفقيط (المبلغ كتابةً)

دوال نقية بلا أي اعتماديات، تحوّل مبلغاً عشرياً (نص) إلى كلمات بالعربية أو الإنجليزية لعملة معيّنة.

```ts
import { amountToWords, JOD } from '@cheques/words';

amountToWords({ amount: '3355.515', currency: JOD, lang: 'ar' });
// "ثلاثة آلاف وثلاثمائة وخمسة وخمسون دينارا و 515 فلس"

// لمطابقة وحدة الإكسل/VBA (وفيها عبارة الإغلاق) مرّر الخيار صراحةً:
amountToWords({ amount: '3355.515', currency: JOD, lang: 'ar', closing: true });
// "ثلاثة آلاف وثلاثمائة وخمسة وخمسون دينارا و 515 فلس فقط"
```

## عبارة الإغلاق

- **الناتج الافتراضي لا يحتوي «فقط» ولا `Only`** (`closing: false` افتراضياً)، التزاماً بـ `DESIGN.md` §6:
  عبارة الإغلاق ليست جزءاً من التفقيط، بل تُضاف في **قالب الطباعة لكل بنك** («فقط» أو «فقط لا غير»).
- من يحتاج الناتج القديم (مطابقة Excel/VBA) يمرّر `closing: true`.
- اختبار انحدار يمنع عودة «فقط»/`Only` إلى الناتج الافتراضي: `ar.test.ts` و`en.test.ts`.

## قواعد التصميم

- **المبلغ نص عشري دائماً** (`"3355.515"`) ولا يُقبل `number`. التحليل بـ `BigInt` بلا floating point.
- **لا تقريب صامت:** كسور أكثر من خانات العملة (إلا أصفاراً زائدة) ترمي `TOO_MANY_DECIMALS`.
  الاستيراد من الإكسل يجب أن يقرّب القيم القادمة منه (مثل `514.99999999987267`) **قبل** استدعاء هذه الدالة.
- **خانات العملة مُتحقَّق منها:** `minorDigits` يجب أن يكون عدداً صحيحاً في المدى 0..6، وإلا يُرمى
  `INVALID_AMOUNT` (رمز قائم، بلا رموز جديدة).
- **العملة بيانات** (`currencies.ts`): المفرد والجمع والجنس ووحدة الكسر وعدد الخانات. إضافة عملة = إضافة سطر.
- `fractionStyle`: `numeric` (« و 515 فلس » كما في الإكسل الحالي) أو `words`.
- حتى 18 خانة للجزء الصحيح.

## الاختبارات

```
npx vitest run packages/words      # من جذر المستودع (Vitest، pool: 'threads')
npm test                           # الاختبارات كلها من الجذر
npm test --workspace @cheques/words
```

- `ar.test.ts` و`en.test.ts`: حالات مكتوبة من قواعد اللغة، ومنها الحالة المأخوذة من ورقة الإكسل
  (تمرّ `closing: true` صراحةً لأن المتوقّع مأخوذ من وحدة VBA).
- `golden.test.ts`: يقارن مع مخرجات وحدة VBA الحالية إذا وُضع الملف `test/golden/jod-ar.csv`
  (يُولَّد بماكرو `tools/TafqeetGoldenExport.bas`). الفروق المقبولة تُوثَّق في `test/golden/known-differences.json`
  بصيغة `{ "201000.000": "السبب" }`. بدون الملف **يُتخطّى** الاختبار برسالة تبيّن السبب.
- ملف ذهبي فارغ أو بترويسة فقط **يفشل بصوت عالٍ**، والمبلغ غير القابل للتحليل (مثل `514.99999999987267`
  أو `1e3`) يُدرَج في الفروق كتشخيص بدل أن يُسقط التشغيل كله.
- تقرير الفروق: `node tools/compare-golden.ts test/golden/jod-ar.csv`

> ملاحظة بيئة: صندوق حماية DSH على ويندوز يمنع العمليات الفرعية بأنابيب stdio، وVite يبني ملف إعداد
> Vitest بـ esbuild (وهو يشغّل خدمته بعملية فرعية) — لذلك `npx vitest run` يحتاج صلاحية موسّعة محلياً،
> ويعمل في CI بلا أي إعداد إضافي. التفاصيل في `AGENTS.md` (قيود البيئة).

## الفروق المتوقعة عن وحدة VBA (للمراجعة بعد التصدير)

- 201,000 و202,000 ونحوها: نكتب «مائتا ألف وألف»، والوحدة قد تكتب «مائتان ألف وألف».
- الكسر الرقمي: «5 سنتات» لعملات مثل الدولار (الوحدة تستعمل المفرد دائماً)، ولا فرق للدينار والفلس.
